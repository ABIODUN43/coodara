# 1. Sprint Philosophy

We build Codara in small, testable increments.

Each sprint should produce software that works.

No sprint should leave the project in a broken state.

Every sprint ends with:

• Demo

• Code Review

• Testing

• Documentation Update

---

# 2. Sprint Duration

Each sprint lasts **2 weeks**.

Week 1

• Planning

• Development

• Daily standups

Week 2

• Development

• Testing

• Review

• Sprint Demo

# 14. Sprint Review

At the end of every sprint:

Demonstrate completed features.

Review completed tasks.

Verify acceptance criteria.

Merge approved Pull Requests.

Update documentation.

---

# 15. Sprint Retrospective

Discuss:

What went well?

What went poorly?

What blocked progress?

How can we improve?

Every team member participates.

---

# 16. Definition of Done

A task is complete only when:

✓ Code implemented

✓ Tests pass

✓ Documentation updated

✓ Code reviewed

✓ CI passes

✓ Feature demonstrated

✓ No critical bugs

✓ Merged into main branch
